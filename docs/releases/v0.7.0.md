`AltScreen` now runs the whole flow as one Bubble Tea program on the program's own alternate screen. Before, each screen drew inline on an alternate screen that teakit entered by hand, and terminals such as iTerm2 kept every erased frame in the scrollback. Inside `AltScreen`, runners ignore their own program options; pass options such as `tea.WithInput` through the new trailing `opts` of `AltScreen`, but not `tea.WithFilter`, which would see the flow's own messages instead of what the screens receive. Print nothing to the terminal while the flow runs, since the program owns it; show work in progress with `Wait`. Ctrl+C between screens is now a key the program handles, so a second one no longer exits the process: work between screens has to stop when the flow's context is cancelled.

`Wait` runs `work` as a Bubble Tea command. A panic in `work` ends the program and restores the terminal, and `Wait` returns the program's error.

Fixes in the step screens:
- Ctrl+V pastes into a list's field.
- While the leave question is up, the screen under it no longer changes or ends: pasted text is dropped, and anything else that arrives for the screen waits until the user stays.
- On a short terminal the leave question drops its text, then its hint, to keep its options in view. When even the options cannot fit, it asks to enlarge the terminal, and only Ctrl+C acts.
- A field without `Accept` takes any text instead of panicking on Enter.
- Keys on a list without options do nothing instead of panicking.
- `Wrap` splits an over-long word by terminal cells, so wide characters stay inside the column.
- `AskLeave` draws its question like a `Step` without `List` or `Form`, folded to the terminal width.
- Under `AltScreen`, runners called at the same time from several goroutines show their screens one after another, and a later screen no longer receives the messages of an earlier screen's commands. Effects that only Bubble Tea acts on, such as `tea.Raw`, act on the shared program and can still take effect after their screen ends.
- Screens ask the terminal for key event types, so where the terminal reports key repeats, a held Enter cannot confirm the diff.

In the diff view:
- A host that embeds `NewDiff` must run its `Init` command and every command `Update` returns. Enter, the alternate key, and `y` act only after a settle message that the diff schedules once a ready frame shows diff data.
- A size from `SetSize` now wins over later `tea.WindowSizeMsg` values, and `WithFiles` keeps its own copy of the content.
- Page Down pages by the height actually shown under the pinned file context, and a resize keeps the top source line in view as far as the scroll range allows.
- The answers need a visible diff line or `(empty)`/`(absent)` placeholder, not just headings or notes, and a refused answer always says why.
- The hint line is built with bubbles/help. When narrow it drops scrolling hints before the answer and Esc. It shows `y accept` while the acknowledgement is pending, and no longer shows an alternate key that scrolling already uses, or an answer while no diff line is visible.
- Tabs after wide characters, wrapped continuation lines, control bytes next to literal backslash text, and leave titles that carry escape sequences now render correctly.
