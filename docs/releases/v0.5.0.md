`AltScreen` now handles Ctrl+C between screens itself, so interrupting the flow outside a program no longer leaves the terminal on the alternate screen. This changes its signature.

Migrate each call: pass a context first, take the flow's context in the callback, and run every screen inside with that context.

```go
// v0.4.0
err := teakit.AltScreen(os.Stderr, func() error {
    return runWizard(ctx)
})

// v0.5.0
err := teakit.AltScreen(ctx, os.Stderr, func(ctx context.Context) error {
    return runWizard(ctx) // every Step.Run, Wait, AskLeave, and ReviewDiff gets this ctx
})
```

The first interrupt or termination signal while the flow runs cancels the flow's context with `ErrLeave` as its cause. The next screen then answers as if Ctrl+C was pressed on it: `ErrLeave` from `Step.Run` and `Wait`, `Interrupt` from `AskLeave`, and `DiffInterrupt` from `ReviewDiff`, so existing Ctrl+C handling covers it. A screen given the outer context does not see the signal, and the Ctrl+C is lost. A `signal.NotifyContext` added only for `AltScreen` can be removed. A second signal is not caught and exits without leaving the alternate screen. Callers that do not use `AltScreen` need no changes.

Update with `go get github.com/undervoke/teakit@v0.5.0`. See the [integration guide](https://github.com/undervoke/teakit/blob/v0.5.0/docs/consumers.md#adopt-the-step-runner).
